# Docs Skill

## 적용 범위

README, 프로젝트 문서, 작업 지침 문서 수정에 적용한다.

대상 예시:
- `README.md`
- `AGENTS.md`
- `.agents/**/SKILL.md`
- 개발/운영 설명 문서

## README 규칙

- README는 현재 실제 기능 기준으로 설명한다.
- 오래된 “추후 예정”, “스캐폴드 수준”, “목 데이터 기반” 설명이 실제 구현과 다르면 현재 상태 기준으로 갱신한다.
- 기능 소개는 단순 나열보다 손님 흐름과 운영자 흐름이 드러나도록 자연스럽게 작성한다.
- 실행 포트와 환경변수는 실제 현재 설정과 맞춘다.

## 문서 톤

- 자연스럽고 읽히는 한국어를 우선한다.
- 개발자에게 필요한 구조와 실행 방법은 명확하게 적는다.
- 제품 소개처럼 보이는 부분과 개발 문서처럼 보여야 하는 부분을 구분한다.
- 과장된 표현보다 실제 구현된 기능을 정확히 소개한다.

## AGENTS / SKILL 문서 규칙

- `AGENTS.md`에는 공통 규칙과 영역별 지침 위치를 둔다.
- 세부 영역 규칙은 `.agents/**/SKILL.md`에 나눠 둔다.
- 프로젝트 구조가 바뀌면 관련 지침도 함께 갱신한다.
- 중복이 너무 많아지면 루트 문서는 짧게 유지하고 영역 문서로 옮긴다.

## 검증

- 문서 수정 후 빌드나 테스트는 실행하지 않는다.
- 문서 내용이 실제 구현과 맞는지 필요한 범위에서만 확인한다.
